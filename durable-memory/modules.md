# Module Store Architecture & Invariants

This document details the design, disk layout, spec grammar, security invariants, atomic write policy, and error model for `@lmctl-ai/lmts/modules`.

---

## 1. Overview & Purpose

The Module Store (`@lmctl-ai/lmts/modules`) is a Node.js-based caching and lifecycle engine for distributed CLI modules declared in `cli.schema.v1` format. It provides local caching, integrity verification, atomic installation, updates, and uninstallation for schemas fetched from GitHub.

Both LMScript (`lmscript`) and administrative tools (`lmbee`) utilize this module store:
- **`lmscript`**: Automatically resolves cached modules on import (e.g. `import "@lmctl-ai/lmgit"`), transparently fetching and installing on a cache miss during execution.
- **`lmbee`**: Provides administrative CLI commands (`lmbee install`, `lmbee list`, `lmbee upgrade`, `lmbee remove`).

---

## 2. Module Spec Grammar

A module spec identifies a repository and channel:

```text
@<owner>/<repo>[#<channel>]
```

### Parsing Rules

- **Owner**: `^[A-Za-z0-9][A-Za-z0-9._-]*$`
  - Must begin with an alphanumeric character.
  - Cannot be `.` or `..`.
- **Repo**: `^[A-Za-z0-9][A-Za-z0-9._-]*$`
  - Must begin with an alphanumeric character.
  - Cannot be `.` or `..`.
- **Channel**:
  - When `#<channel>` is omitted, defaults to `channel = 'latest'`.
  - Supported channels are `latest` and `dev`.
  - Any other `#...` (tags, branches, commits, traversal) returns code `SPEC_CHANNEL` with message `"only the latest and dev channels are supported"`.
- Any owner/repo syntax error returns a `Result` error with code `SPEC_SYNTAX`.

### Moving Channels & Evergreen Architecture

Both `latest` and `dev` are moving channels representing upstream default branch schemas:
- **`latest`**: Stable, published release contract.
- **`dev`**: Active development contract.
Wrappers evolve additively and enforce their own product version requirements via `UNSUPPORTED_PRODUCT_VERSION`. As a result, the local cache functions as an **evergreen freshness cache** rather than an immutable pin.

## 3. Cache Directory Layout

Modules are stored on the local filesystem under the cache root:

```text
${LMCTL_HOME:-~/.lmctl}/modules/
└── github.com/
    └── <owner>/
        └── <repo>/
            └── <channel>/
                ├── CURRENT
                └── generations/
                    └── gen-<timestamp>-<uuid>/
                        ├── cli.schema.<channel>.json
                        └── meta.json
```

### Components:
- **Cache Root**: Determined by `cacheRoot(env?)`:
  - `env.LMCTL_HOME/modules` if non-empty.
  - `resolve(env.HOME, '.lmctl', 'modules')` or `os.homedir()/.lmctl/modules`.
- **Hostname Prefix**: `github.com` namespace isolates GitHub sources and reserves room for future providers.
- **Channel Directory**: `latest` or `dev`.
- **Path Traversal Protection**: Every path generated by `entryDir(root, spec)` is strictly checked to ensure:
  1. It is a descendant of the resolved `root`.
  2. It is a descendant of `resolve(root, 'github.com')`.
  Any escaping path triggers a `PATH_TRAVERSAL` error.

## 4. On-Disk Artifacts & Permissions

Each immutable generation contains two files. `CURRENT` names the active generation; readers snapshot it once and read both files from that generation. Entries without `CURRENT` retain legacy fixed-file compatibility:

1. **`cli.schema.<channel>.json`** (`cli.schema.latest.json` or `cli.schema.dev.json`):
   - The raw published schema document fetched from `https://raw.githubusercontent.com/<owner>/<repo>/HEAD/cli.schema.<channel>.json`.
   - File permissions: `0600` (read/write by owner only).
2. **`meta.json`**:
   - Metadata recorded at installation time and updated during freshness revalidations:
     ```json
     {
       "spec": "@owner/repo#latest",
       "channel": "latest",
       "url": "https://raw.githubusercontent.com/owner/repo/HEAD/cli.schema.latest.json",
       "sha256": "abcdef...",
       "fetched_at": "2026-10-10T12:00:00.000Z",
       "last_checked": "2026-10-10T12:00:00.000Z",
       "etag": "\"abcdef123456\"",
       "tool": "lmgit",
       "version": "1.0.0",
       "bytes": 14205
     }
     ```
   - File permissions: `0600` (read/write by owner only).
- **Directory Permissions**: Entry directories and parent owner/repo directories are created with mode `0700` (`rwx------`).

## 5. Atomic Write & Fetch Policy

Installation and upgrade operations follow strict safety guarantees:

1. **Streaming Cap (`OUTPUT_LIMIT`)**:
   - Downloads enforce a maximum schema size limit (`MAX_SCHEMA_BYTES = 2 * 1024 * 1024` = 2 MiB).
   - If the incoming stream exceeds 2 MiB, the request is aborted and an `OUTPUT_LIMIT` error is returned.
2. **Schema Validation (`INVALID_SCHEMA`)**:
   - Fetched content is parsed as JSON (`BAD_JSON` on parse failure).
   - The schema is validated via `parsePublishedSchema()`. Schemas with missing required fields, reserved names (`__proto__`, `constructor`, `prototype`), or invalid syntax are rejected.
3. **Atomic Writes (`ATOMIC_WRITE_FAILED`)**:
   - Schema and metadata are staged and renamed inside a new immutable generation directory.
   - Only after both files are complete is a temporary pointer renamed to `CURRENT`.
   - 304 freshness updates publish a complete generation too; existing reader snapshots remain valid.
   - A failed write or publication leaves the previous pointer and generation intact. Temporary files are removed; abandoned generations remain.
   - Malformed pointers, missing generations, and incomplete active generations return `CACHE_CORRUPT` without legacy fallback.

## 6. Verification & Tamper Detection

`resolveCached(spec, options?)`:
- Computes SHA-256 of the on-disk `cli.schema.<channel>.json`.
- Compares against `meta.json`'s `sha256`.
- If the hash differs or metadata is corrupt, returns `CACHE_CORRUPT` naming the corrupt file with a remediation hint (`run: lmbee module install <key> --force`).
- Validates the document with `parsePublishedSchema()`, returning `INVALID_SCHEMA` on schema violations.

## 7. Lifecycle Operations

- **`ensure(spec, options?)`**:
  - Checks existing cached entry and its age against `ttlMs` (default 6 hours).
  - Age < TTL: returns `{ source: 'cache', module }` immediately with zero network requests.
  - Age $\ge$ TTL and `update = true`: sends conditional GET (`If-None-Match: <etag>`) with 3 s timeout.
    - `304 Not Modified`: publishes an immutable generation with updated `last_checked` and returns `{ source: 'network', module }`.
    - `200 OK`: validates schema, atomically replaces on-disk files, and returns `{ source: 'network', module }`.
    - Any failure (network, timeout, HTTP error, bad JSON, invalid schema, write failure): falls back to the existing cached module returning `{ source: 'stale-cache', module, warning }`. The previous active generation remains byte-identical; failed writes can leave unreferenced generations.
  - `update = false`: returns cached module regardless of age without network (`source: 'cache'`).
  - Cache miss + `install = true`: calls `install()` and returns `{ source: 'installed', module }`.
  - Cache miss + `install = false`: returns `NOT_INSTALLED` error with `run: lmbee module install <key>`.
  - Cache corrupt: returns `CACHE_CORRUPT` error unchanged (never silently refetched).
- **`install(spec, options?)`**:
  - Checks if already installed. If sha matches and `!force`, returns `unchanged`.
  - Fetches schema from GitHub raw URL, validates, and atomically writes to cache.
  - Returns `{ action: 'installed' | 'replaced' | 'unchanged', entry }`.
- **`list(options?)`**:
  - Traverses `${root}/github.com/*/*/*`.
  - Verifies integrity of each entry.
  - Reports entry including `spec`, `channel`, `version`, `sha256`, `fetchedAt`, and `binaryOnPath`.
  - If corrupt, reports entry with a descriptive `problem` string.
- **`upgrade(spec?, options?)`**:
  - If `spec` omitted or undefined, upgrades all installed moving channel modules (`latest` and `dev`).
  - Refetches upstream schema:
    - If equal: reports `unchanged`.
    - If changed: replaces cached files, computes delta of added and removed operations, and reports `updated` with `fromVersion` and `toVersion`.
- **`remove(spec, options?)`**:
  - Removes the specific channel directory or all channels for the repo (`allChannels: true`).
  - Prunes empty parent directories up to `cacheRoot` to keep the cache tree clean.
- **`findOnPath(executableName, env?)`**:
  - Scans `env.PATH` for an executable matching `executableName`.
  - Returns the resolved absolute path or `null`.

## 8. Error Codes Reference

All operations return a `Result<T>`:
```ts
export type Result<T> =
  | { ok: true; value: T }
  | {
      ok: false;
      error: ModuleError;
      code: ModuleErrorCode;
      message: string;
      file?: string;
      issues?: unknown[];
      details?: Record<string, unknown>;
    };
```

| Code | Description |
| :--- | :--- |
| `SPEC_SYNTAX` | Spec string fails syntax parsing or contains illegal characters. |
| `SPEC_CHANNEL` | Channel is not `latest` or `dev`. |
| `NOT_INSTALLED` | Module or channel does not exist in local cache. |
| `CACHE_CORRUPT` | Schema checksum mismatch or unreadable metadata. |
| `INVALID_SCHEMA` | Schema fails `cli.schema.v1` structural validation. |
| `OUTPUT_LIMIT` | Fetched schema exceeded the 2 MiB size cap. |
| `FETCH_FAILED` | HTTP request to GitHub raw failed or returned non-200/non-304 status. |
| `BAD_JSON` | Schema response or cached file is not valid JSON. |
| `PATH_TRAVERSAL` | Path computation attempted to escape cache directory namespace. |
| `ATOMIC_WRITE_FAILED`| Writing or renaming temporary cache files failed. |

## Known limitations (wiki: amend freely)

- **Generation retention:** old and abandoned generations are retained to keep reader snapshots valid. Garbage collection needs a reader-lifetime protocol and is outside this change. `remove` deletes the entry including generations.
- **Mixed SDK versions:** older SDKs do not understand `CURRENT`. Legacy entries remain readable by the new SDK, but consumers sharing a cache must upgrade together before using generation entries.
- **Redirects:** one same-host hop is followed; anything else is `FETCH_FAILED`.
- **Local attackers:** the store trusts its own directory. A user who can write inside `~/.lmctl/modules`
  can already run code as that user, so symlink games inside the cache are out of scope.
